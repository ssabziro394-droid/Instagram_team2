# Техническое задание: Исмоил (Ismoil)

## Роль и задачи
Ты отвечаешь за представление пользователей в системе — страницу Профиля (Profile) и механизм Поиска (Search). Твоя задача — сделать данные красиво структурированными и легко находимыми.

## Детальный план работ

### 1. Страница Профиля (User Profile)
- [ ] Разработка шапки профиля (Profile Header):
  - Круглая аватарка (большая).
  - Информация: Username, Имя/Фамилия, Биография (Bio), ссылка на сайт.
  - Статистика (счетчики): Публикации, Подписчики (Followers), Подписки (Following).
- [ ] Логика кнопок профиля:
  - Если это мой профиль — кнопка "Редактировать профиль" (Edit Profile).
  - Если чужой — кнопка "Подписаться/Отписаться" (Follow/Unfollow) и кнопка "Написать сообщение".
- [ ] Реализация модального окна "Редактировать профиль" (изменение аватарки, имени, био).
- [ ] Сетка контента (Profile Grid):
  - Вкладки (Tabs): Посты (Grid-иконка), Reels (Видео-иконка), Сохраненные (только для своего профиля), Отметки.
  - Отображение постов в виде квадратных миниатюр (3 в ряд).
  - При наведении (hover) на миниатюру на десктопе — показ иконок лайков и комментариев поверх картинки.

### 2. Модуль Поиска (Search)
- [ ] Разработка компонента строки поиска (Search Input).
- [ ] Реализация выпадающего списка (Dropdown) с результатами поиска, который появляется под строкой поиска.
- [ ] Логика Debounce: отправка запроса на сервер не при каждом нажатии клавиши, а с задержкой (например, 300мс), чтобы не перегружать API.
- [ ] Создание RTK Query эндпоинта `searchUsers` (отправка `query` строки).
- [ ] Разработка UI элемента `UserListItem` (маленькая аватарка, username, имя) для отображения в результатах.
- [ ] Маршрутизация: при клике на результат пользователя должен происходить переход на `/profile/[username]`.

### 3. Интеграция API
- [ ] Создание `getUserProfile` (по username) и `getUserPosts` эндпоинтов.
- [ ] Мутация `toggleFollow` для подписки/отписки с обновлением счетчиков подписчиков.
